# Infrastructure as Code (IaC) Best Practices Summary

## Core Principles

Infrastructure as Code (IaC) treats infrastructure management with the same rigor as application code, enabling version control, faster and safer deployments across environments, and up-to-date documentation. Popular IaC tools include **Terraform**, **Pulumi**, and **CloudFormation**. Terraform uses HCL, a declarative language where you specify desired infrastructure state and Terraform handles creation via API calls to cloud providers.

## Key Best Practices

### 1. Code Quality & Consistency

- **Always format and validate** — Run `terraform fmt` and `terraform validate` on every change to keep code consistent and correct.
- **Adopt consistent naming and folder conventions** — Standardize names for resources, variables, files, and modules so code is predictable to navigate.
- **Keep it simple** — Use advanced features only when necessary; if something feels complicated, look for a simpler solution.

### 2. Version Control

- Keep playbooks, roles, inventory, variables files, and all IaC configurations in git with meaningful commit messages. This provides an audit trail of when and why infrastructure rules changed.

### 3. Tagging & Governance

- **Tag resources consistently** — Apply a standard tag set (e.g., owner, env, cost-center, app) to govern, audit, and track costs.

### 4. Policy as Code (PaC)

- Enforce rules automatically for security, cost, and approvals using tools like **Open Policy Agent (OPA)**, **HashiCorp Sentinel**, or native cloud services like **AWS Config**. This enables automated checks for mandatory tags, forbidden instance types, or overly permissive IAM policies.

### 5. Secrets Management

- Keep secrets out of code and state files. Store them in a dedicated secret manager and pass references, not values.

### 6. Testing

- **Follow a testing pyramid**: Begin with static analysis (linting, format checks), add unit/contract tests, then layer in integration and end-to-end tests.
- **Use IaC testing frameworks**: Terratest (Go-based integration testing for Terraform), Kitchen-Terraform, or Pulumi's built-in testing framework.
- **Create ephemeral test environments**: Configure CI/CD pipelines to spin up temporary, isolated environments for running tests so changes fail fast before reaching production.

### 7. Debugging

- Make debugging and troubleshooting repeatable — enable debug logs only when needed and capture enough context to reproduce issues quickly.
