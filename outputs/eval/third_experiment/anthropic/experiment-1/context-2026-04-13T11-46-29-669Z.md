# Summary: NGINX HTTP Load Balancing and OpenStack Security Groups

## NGINX Load Balancing

NGINX can serve as an efficient HTTP load balancer to distribute traffic across multiple application servers, optimizing resource utilization, maximizing throughput, reducing latency, and ensuring fault tolerance.

### Load Balancing Methods

- **Round-robin** (default): Requests are distributed evenly across servers.
- **Least-connected**: Requests go to the server with the fewest active connections.
- **IP-hash**: A hash function based on client IP determines server selection.
- **Random**: Suited for distributed environments with multiple load balancers.

### Basic Configuration

Servers are defined using the `upstream` directive in the `http` context:

```nginx
http {
    upstream myapp1 {
        server srv1.example.com;
        server srv2.example.com;
        server srv3.example.com;
    }

    server {
        listen 80;

        location / {
            proxy_pass http://myapp1;
        }
    }
}
```

### Server Weights and Backup

Servers can be assigned weights and marked as backups:

```nginx
upstream backend {
    server backend1.example.com weight=5;
    server backend2.example.com;
    server 192.0.0.1 backup;
}
```

A backup server only receives requests when all other servers are unavailable. If no weight is specified, it defaults to 1. Round Robin, Least Connections, and Random methods all respect server weights.

NGINX supports load balancing for HTTP, HTTPS, FastCGI, uwsgi, SCGI, memcached, and gRPC using their respective `*_pass` directives (e.g., `fastcgi_pass`, `grpc_pass`).

## OpenStack Security Groups (Terraform)

When managing OpenStack security groups with Terraform, OpenStack typically creates default egress rules automatically. To fully manage infrastructure with Terraform, set `delete_default_rules` to `true` and explicitly define egress rules:

```hcl
resource "openstack_networking_secgroup_rule_v2" "secgroup_rule_v4" {
  direction         = "egress"
  ethertype         = "IPv4"
  security_group_id = openstack_networking_secgroup_v2.secgroup.id
}

resource "openstack_networking_secgroup_rule_v2" "secgroup_rule_v6" {
  direction         = "egress"
  ethertype         = "IPv6"
  security_group_id = openstack_networking_secgroup_v2.secgroup.id
}
```

Security groups can be imported into Terraform using:

```
$ terraform import openstack_networking_secgroup_v2.secgroup_1 38809219-5e8a-4852-9139-6f461c90e8bc
```

Default rule behavior may vary depending on the OpenStack cloud configuration.
