NGINX can be used as an efficient HTTP load balancer to distribute traffic across multiple application instances for better utilization, throughput, latency, scalability, reliability, and fault tolerance.

To configure load balancing, define an `upstream` group in the `http` context and list backend servers with `server` directives. Then proxy requests to that upstream from a `server` block. If no method is specified, NGINX uses round-robin by default.

```nginx
http {
    upstream myapp1 {
        server srv1.example.com;
        server srv2.example.com;
        server srv3.example.com;
    }

    server {
        listen 80;

        location / {
            proxy_pass http://myapp1;
        }
    }
}
```

Supported HTTP load-balancing methods mentioned in the docs include:

- round-robin (default)
- least-connected
- ip-hash
- random

Weights can be assigned per backend with the `weight` parameter; if omitted, the default weight is `1`. A server marked `backup` only receives requests when the non-backup servers are unavailable.

```nginx
upstream backend {
    server backend1.example.com weight=5;
    server backend2.example.com;
    server 192.0.0.1 backup;
}
```

NGINX reverse proxy load balancing also applies to HTTPS and other upstream protocols, using the appropriate pass directives such as `fastcgi_pass`, `uwsgi_pass`, `scgi_pass`, `memcached_pass`, and `grpc_pass`. Additional related controls mentioned include `proxy_next_upstream`, `backup`, `down`, and `keepalive`.
