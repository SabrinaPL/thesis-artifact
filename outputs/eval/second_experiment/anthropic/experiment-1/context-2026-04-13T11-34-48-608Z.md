# Summary: OpenStack Security Groups with Terraform

## Security Group Resource (`openstack_networking_secgroup_v2`)

The Terraform OpenStack provider manages Neutron security groups, which separate the group definition from its rules (unlike Nova security groups). An admin can also target a specific `tenant_id`.

### Basic Usage

```
resource "openstack_networking_secgroup_v2" "secgroup_1" {
  name        = "secgroup_1"
  description = "My neutron security group"
}
```

### Key Arguments
- **`name`** (Required): A unique name for the security group.
- **`description`** (Optional): Description of the security group.
- **`tenant_id`** (Optional): The owner of the security group. Required if an admin creates it for another tenant.
- **`delete_default_rules`** (Optional): Whether to delete the default egress security rules.
- **`region`** (Optional): The region for the V2 networking client. Falls back to the provider's region if omitted.

### Default Egress Rules

OpenStack typically creates default egress rules (IPv4 and IPv6) for each new security group. These are **not managed by Terraform**. To have Terraform fully manage all rules, set `delete_default_rules` to `true` and explicitly define egress rules:

```
resource "openstack_networking_secgroup_rule_v2" "secgroup_rule_v4" {
  direction         = "egress"
  ethertype         = "IPv4"
  security_group_id = openstack_networking_secgroup_v2.secgroup.id
}

resource "openstack_networking_secgroup_rule_v2" "secgroup_rule_v6" {
  direction         = "egress"
  ethertype         = "IPv6"
  security_group_id = openstack_networking_secgroup_v2.secgroup.id
}
```

Note: Default rule behavior varies by OpenStack cloud configuration.

## Security Group Rule Resource (`openstack_networking_secgroup_rule_v2`)

Rules are managed as separate resources, referencing the security group by ID.

### Example: Allow SSH Ingress

```
resource "openstack_networking_secgroup_rule_v2" "secgroup_rule_1" {
  direction        = "ingress"
  ethertype        = "IPv4"
  protocol         = "tcp"
  port_range_min   = 22
  port_range_max   = 22
  remote_ip_prefix = "0.0.0.0/0"
  security_group_id = openstack_networking_secgroup_v2.secgroup_1.id
}
```

### Key Arguments for Rules
- **`direction`**: `ingress` or `egress`.
- **`ethertype`**: `IPv4` or `IPv6`.
- **`protocol`**: e.g., `tcp`, `udp`, `icmp`.
- **`port_range_min`** / **`port_range_max`**: Port range for the rule.
- **`remote_ip_prefix`**: CIDR for allowed remote addresses.
- **`security_group_id`**: The security group this rule belongs to.
- **`description`** (Optional): Description of the rule.
- **`region`** (Optional): Falls back to provider region.

## Importing Existing Security Groups

Security groups can be imported into Terraform state:

```
$ terraform import openstack_networking_secgroup_v2.secgroup_1 38809219-5e8a-4852-9139-6f461c90e8bc
```

## Provider Configuration

The OpenStack provider requires proper authentication credentials:

```
terraform {
  required_version = ">= 0.14.0"
  required_providers {
    openstack = {
      source  = "terraform-provider-openstack/openstack"
      version = "~> 1.53.0"
    }
  }
}

provider "openstack" {
  user_name   = "admin"
  tenant_name = "admin"
  password    = "pwd"
  auth_url    = "http://myauthurl:5000/v3"
  region      = "RegionOne"
}
```
