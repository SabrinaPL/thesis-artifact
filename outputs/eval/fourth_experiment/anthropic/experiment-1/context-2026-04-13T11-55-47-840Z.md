# Summary: Infrastructure as Code (IaC) Best Practices with Terraform and Ansible

## Core Value Proposition of IaC

Infrastructure as Code tools like Terraform and Ansible enable managing and provisioning computing infrastructure through machine-readable configuration files rather than manual processes. This approach delivers value across key dimensions:

- **Repeatability**: Using the same configuration files across development, staging, and production environments ensures identical infrastructure, eliminating environment drift by design.
- **Audibility**: Every change is a Git commit, providing a permanent record of who changed what, when, and why.

## Terraform Best Practices

1. **Use version control and prevent manual changes**: Treat infrastructure configurations as application code. Embrace a GitOps approach and implement automated CI/CD workflows to apply changes.

2. **Shift culture to collaborative IaC**: Enable usage across teams with self-service infrastructure, apply policies and compliance according to organizational standards.

3. **Use formatting and validation tools**: Run `terraform fmt` and `terraform validate` as part of CI pipelines, with human approval before anything is applied.

4. **Provisioners as a last resort**: Terraform is primarily designed for immutable infrastructure. Use purpose-built solutions for post-apply operations (uploading files, running commands/scripts). Only use Terraform provisioners when no provider-native mechanism exists.

## Ansible for IaC

Ansible supports **mutable infrastructure**, where changes are applied directly to existing systems. This offers flexibility for rapid changes but can accumulate configuration drift over time. Organizations can address drift through periodic playbook execution and monitoring.

Ansible can provision complete AWS infrastructure stacks including VPC networking, security groups, EC2 instances, and Application Load Balancers, then deploy applications (e.g., Nginx web servers) on the provisioned instances.

To clean up resources after deployment:

```
ansible-playbook playbooks/teardown.yml
```

## Multi-Tool Orchestration

Platforms like Spacelift can manage infrastructure tools including Ansible, Terraform, OpenTofu, Pulumi, AWS CloudFormation, and Kubernetes from a single place, combining their stacks and building workflows across tools. This enables custom workflows based on pull requests and compliance checks.
