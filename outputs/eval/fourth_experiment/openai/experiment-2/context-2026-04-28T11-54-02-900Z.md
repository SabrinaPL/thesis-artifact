# Retrieval Context

## Prompt Label

FOURTH_EXPERIMENT

## Model

openai

In Terraform OpenStack, `openstack_networking_secgroup_v2` manages Neutron security groups, while `openstack_networking_secgroup_rule_v2` manages the individual rules.

A key behavior is that OpenStack often creates default **egress** rules automatically when a new security group is created. These default rules are typically **not managed by Terraform**. If you want Terraform to fully control the security group contents, set `delete_default_rules = true` on the security group and then explicitly create the egress rules yourself. The provider docs note this behavior can vary by cloud: some environments may add extra default rules, and some may add none at all.

Example from the provider docs:

```hcl
resource "openstack_networking_secgroup_rule_v2" "secgroup_rule_v4" {
  direction = "egress"
  ethertype = "IPv4"
  security_group_id = openstack_networking_secgroup_v2.secgroup.id
}

resource "openstack_networking_secgroup_rule_v2" "secgroup_rule_v6" {
  direction = "egress"
  ethertype = "IPv6"
  security_group_id = openstack_networking_secgroup_v2.secgroup.id
}
```

For rule creation, `openstack_networking_secgroup_rule_v2` supports defining properties like direction, ethertype, protocol, port ranges, remote CIDR, and the target security group. Example ingress rule:

```hcl
resource "openstack_networking_secgroup_v2" "secgroup_1" {
  name = "secgroup_1"
  description = "My neutron security group"
}

resource "openstack_networking_secgroup_rule_v2" "secgroup_rule_1" {
  direction = "ingress"
  ethertype = "IPv4"
  protocol = "tcp"
  port_range_min = 22
  port_range_max = 22
  remote_ip_prefix = "0.0.0.0/0"
  security_group_id = openstack_networking_secgroup_v2.secgroup_1.id
}
```

This matches typical OpenStack behavior shown in Nova documentation, where newly created security groups include IPv4 and IPv6 egress rules by default.

Existing security groups can be imported by ID:

```sh
$ terraform import openstack_networking_secgroup_v2 secgroup_1 38809219-5e8a-4852-9139-6f461c90e8bc
```
