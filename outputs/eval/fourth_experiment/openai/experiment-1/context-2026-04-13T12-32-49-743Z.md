# Retrieval Context

## Prompt Label
FOURTH_EXPERIMENT

## Model

Terraform best practices in the retrieved docs center on treating infrastructure as code: keep configurations in version control, avoid manual changes, and use Git/GitOps-style workflows so changes are reviewable, repeatable, and auditable across environments. A collaborative IaC process is recommended, supported by automated CI/CD workflows, policy checks, and human review before apply.

For AI-assisted workflows, the guidance is to let AI suggest changes, then run formatting and validation, and rely on a CI-generated plan plus human approval before applying. For rapid prototyping or short-lived environments, Spacelift Intent is mentioned as an early-access option that provisions from natural-language requests while still keeping guardrails such as policies, audit trail, state, and permissions.

Terraform is intended primarily for immutable infrastructure management. For post-apply actions like uploading files or running scripts, HashiCorp recommends using provider-native or other purpose-built solutions first. Provisioners exist for cases where no better mechanism is available, but they are not the preferred approach.

The retrieved material also highlights the broader value of IaC: replacing manual “ClickOps” with configuration-driven infrastructure improves consistency, reduces drift, and creates a permanent change history through source control.
