````text
# Review of the original generated IaC

## What was good
The original solution already did many things well:

- provisioned one VM on OpenStack
- created a security group
- allowed SSH and HTTP
- used variables for SSH key name and private key path
- used Ansible to install and enable nginx
- deployed a static HTML page
- avoided hardcoding the SSH private key directly in code
- generated a usable Ansible inventory automatically

## What needed improvement
A few areas could be improved:

1. **Credentials handling**
   - The example `terraform.tfvars.example` included `password = "change-me"`.
   - Even in an example, it is better to strongly encourage using OpenStack environment variables or a secrets manager instead of putting credentials in tfvars files.

2. **Security group exposure**
   - SSH and HTTP were both open to `0.0.0.0/0`.
   - HTTP open to the internet is often expected for a web server, but SSH should usually be restricted to an admin IP range.
   - Best practice is to make source CIDRs variables.

3. **Sensitive variables**
   - `private_key_path` is not a secret by itself, but OpenStack auth values are sensitive and should be treated carefully.
   - Outputs should avoid exposing anything unnecessary.

4. **Beginner clarity**
   - The code worked, but adding stronger comments helps junior engineers understand why each resource exists.

5. **Validation**
   - Some variables could benefit from basic validation to catch bad values earlier.
````

## `main.tf`

```hcl
###############################################
# Security group for the web server instance  #
###############################################

resource "openstack_networking_secgroup_v2" "web" {
  # A security group acts like a virtual firewall around the instance.
  name                 = "${var.instance_name}-sg"
  description          = "Security group for single web server"
  delete_default_rules = true
}

# Explicit egress rule for IPv4.
# We define egress rules ourselves so Terraform fully manages the rule set.
resource "openstack_networking_secgroup_rule_v2" "egress_ipv4" {
  direction         = "egress"
  ethertype         = "IPv4"
  security_group_id = openstack_networking_secgroup_v2.web.id
}

# Explicit egress rule for IPv6.
resource "openstack_networking_secgroup_rule_v2" "egress_ipv6" {
  direction         = "egress"
  ethertype         = "IPv6"
  security_group_id = openstack_networking_secgroup_v2.web.id
}

# Allow inbound SSH so Ansible and administrators can connect.
# Best practice: restrict this to a trusted CIDR, not the whole internet.
resource "openstack_networking_secgroup_rule_v2" "ssh_ingress" {
  direction         = "ingress"
  ethertype         = "IPv4"
  protocol          = "tcp"
  port_range_min    = 22
  port_range_max    = 22
  remote_ip_prefix  = var.ssh_allowed_cidr
  security_group_id = openstack_networking_secgroup_v2.web.id
  description       = "Allow SSH from trusted network"
}

# Allow inbound HTTP so users can reach the nginx web server.
resource "openstack_networking_secgroup_rule_v2" "http_ingress" {
  direction         = "ingress"
  ethertype         = "IPv4"
  protocol          = "tcp"
  port_range_min    = 80
  port_range_max    = 80
  remote_ip_prefix  = var.http_allowed_cidr
  security_group_id = openstack_networking_secgroup_v2.web.id
  description       = "Allow HTTP"
}

########################
# Compute instance     #
########################

resource "openstack_compute_instance_v2" "web" {
  # This creates one VM instance.
  name            = var.instance_name
  image_name      = var.image_name
  flavor_name     = var.flavor_name
  key_pair        = var.ssh_key_name
  security_groups = [openstack_networking_secgroup_v2.web.name]

  # Attach the instance to the chosen network.
  network {
    name        = var.network_name
    fixed_ip_v4 = var.instance_fixed_ip_v4
  }
}

########################
# Floating IP          #
########################

# A floating IP provides public connectivity to the instance.
resource "openstack_networking_floatingip_v2" "web" {
  pool = var.floating_network_name
}

# Associate the public floating IP to the VM.
resource "openstack_compute_floatingip_associate_v2" "web" {
  floating_ip = openstack_networking_floatingip_v2.web.address
  instance_id = openstack_compute_instance_v2.web.id
}

##############################################
# Local files used by the Ansible workflow   #
##############################################

# Generate a simple inventory file for Ansible.
# This lets us avoid manually typing the server IP after Terraform completes.
resource "local_file" "ansible_inventory" {
  filename = "${path.module}/inventory.ini"
  content  = <<-EOT
    [web]
    ${openstack_networking_floatingip_v2.web.address} ansible_user=${var.ssh_user} ansible_ssh_private_key_file=${var.private_key_path}
  EOT
}

# Generate the HTML file locally so Ansible can copy it to the server.
resource "local_file" "web_content" {
  filename = "${path.module}/generated-index.html"
  content  = var.web_content
}
```

# Improved Ansible playbook

## `playbook.yml`

```yaml
---
- name: Configure OpenStack web server
  hosts: web
  become: true

  vars:
    # Keeping these as variables makes the playbook easier to adapt later.
    nginx_package: nginx
    nginx_service: nginx
    web_root: /var/www/html
    index_file: /var/www/html/index.html
    local_index_src: ./generated-index.html

  tasks:
    - name: Wait for SSH to become available
      # New VMs often need some time before SSH is ready.
      # This avoids failing immediately if the OS is still booting.
      ansible.builtin.wait_for_connection:
        timeout: 300

    - name: Install nginx using the system package manager
      # The "package" module is portable across Linux distributions because
      # it delegates to apt, dnf, yum, etc. automatically.
      ansible.builtin.package:
        name: '{{ nginx_package }}'
        state: present

    - name: Ensure web root directory exists
      ansible.builtin.file:
        path: '{{ web_root }}'
        state: directory
        owner: root
        group: root
        mode: '0755'

    - name: Deploy static HTML page
      # This copies the locally generated file onto the remote server.
      ansible.builtin.copy:
        src: '{{ local_index_src }}'
        dest: '{{ index_file }}'
        owner: root
        group: root
        mode: '0644'

    - name: Ensure nginx service is enabled and started
      # "enabled: true" means nginx will start automatically on reboot.
      # "state: started" ensures it is running right now.
      ansible.builtin.service:
        name: '{{ nginx_service }}'
        enabled: true
        state: started
```

# Execution instructions

## 1. Set OpenStack credentials securely

Prefer environment variables instead of writing credentials into `.tfvars`.

Example:

```bash
export OS_AUTH_URL="https://openstack.example.com:5000/v3"
export OS_USERNAME="my-user"
export OS_PASSWORD="my-password"
export OS_PROJECT_NAME="my-project"
export OS_USER_DOMAIN_NAME="Default"
export OS_PROJECT_DOMAIN_NAME="Default"
export OS_REGION_NAME="RegionOne"
```

Depending on your OpenStack environment, variable names may differ slightly.

If your provider setup requires Terraform variables instead, pass them securely at runtime or via a protected secrets mechanism in CI/CD.

---

## 2. Prepare your Terraform variable file

```bash
cp terraform.tfvars.example terraform.tfvars
```

Edit `terraform.tfvars` and set your non-secret values:

- image name
- flavor
- network names
- SSH key name
- private key path
- SSH username
- allowed CIDRs
- web page content

Validate formatting and syntax:

```bash
terraform fmt
terraform validate
```


Review carefully before applying, especially:

- selected image and flavor
- network name

- SSH source CIDR
- HTTP source CIDR

## 5. Apply infrastructure

```bash
terraform apply
```

Terraform will:

- create one security group
- add ingress rules for SSH and HTTP
- add egress rules
- create one VM
- allocate and attach a floating IP
- generate:
  - `inventory.ini`
  - `generated-index.html`

---

## 6. Run Ansible to configure nginx

```bash
ansible-playbook -i inventory.ini playbook.yml
```

This will:

- wait for SSH
- install nginx
- ensure the web root exists
- deploy `/var/www/html/index.html`
- enable and start nginx as a system service
