Infrastructure as Code (IaC) is the practice of managing infrastructure through code so environments can be created, changed, and tracked more safely and consistently. The retrieved sources emphasize that using a tool like Terraform, Pulumi, CloudFormation, or Ansible is only the starting point; maintainability comes from disciplined practices.

Common best practices across the documents include:

- Keep infrastructure definitions in version control to provide history, collaboration, and traceability.
- Prefer simple, consistent designs over unnecessary complexity.
- Standardize naming, folder structure, and module organization so configurations are predictable to navigate and maintain.
- Run formatting and validation checks on every change to keep code consistent and catch errors early.
- Apply consistent resource tagging for governance, auditing, and cost tracking.
- Use policy as code to enforce rules such as required tags, restricted instance types, security constraints, and approval guardrails.
- Establish a secrets management approach that avoids storing secrets directly in code or state, using secret managers and references instead.
- Add automated testing at multiple levels: linting and static checks first, then unit or contract tests, followed by a smaller number of integration or end-to-end tests.
- Use established IaC testing tools rather than building everything from scratch; examples mentioned include Terratest, Kitchen-Terraform, Pulumi’s testing framework, OPA, Sentinel, AWS Config, and Ansible callback/customization features where relevant.
- Create ephemeral test environments in CI/CD pipelines so infrastructure changes can be validated in isolated temporary environments before production.
- Make debugging and troubleshooting repeatable by capturing enough context and using debug output only when needed.

Terraform-specific context in the retrieved documents highlights declarative configuration with HCL, where desired state is described and Terraform applies changes through cloud provider APIs. Overall, the documents frame IaC best practices as applying software engineering discipline to infrastructure: versioning, validation, testing, policy enforcement, consistency, and secure handling of sensitive data.
