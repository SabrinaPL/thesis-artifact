# Review of the original generated IaC

## What was good

The original solution already did many things correctly:

- used Terraform for provisioning and Ansible for configuration
- created exactly 3 VMs
- used variables for ports `80` and `8082`
- did not assign floating IPs to web servers
- restricted web server HTTP access to the internal subnet
- only exposed load balancer port `8082`
- used NGINX upstream defaults, which gives round-robin behavior
- generated Ansible inventory from Terraform outputs

## Issues found and improved

### 1. Ansible variable recursion bug
Original:

```yaml
web_port: "{{ web_port | default(80) }}"
lb_port: "{{ lb_port | default(8082) }}"
```

This is risky because the variable refers to itself. In practice, inventory already defines these values, so this file is unnecessary and can cause confusion.

### 2. Web servers were private-only, but Ansible tried to connect directly
The inventory used private IPs for `webserver1` and `webserver2`, which is good for isolation.  
However, from your workstation, Ansible usually cannot reach those private IPs unless you are already on that network.

Improvement:
- treat `loadbalancer` as a bastion/jump host
- use `ansible_ssh_common_args` with `ProxyJump` for the web servers

This is much more realistic in OpenStack environments.

### 3. Safer NGINX deployment
The original copied configs and only later ran `nginx -t`.  
Better practice is to validate the configuration before it replaces the active file where possible.

Improvement:
- use Ansible `template` with `validate: "nginx -t -c %s"` for LB config
- validate web config with a dedicated command before restarting

### 4. Secrets example was too casual
The example tfvars contained:

```hcl
openstack_password = "CHANGE_ME"
```

Even as an example, it’s better to steer people to environment variables or excluded secret files.

### 5. Maintainability improvements
I added:
- inline comments for teaching
- clearer bastion-based inventory
- `.gitignore` recommendation
- safer variable descriptions
- explicit notes around Terraform state sensitivity

## `terraform/main.tf`

```hcl
provider "openstack" {
  # Credentials should ideally come from environment variables or a secure
  # secret source. Terraform variables are supported here, but avoid storing
  # secret values in version control.
  auth_url    = var.openstack_auth_url
  region      = var.openstack_region
  tenant_name = var.openstack_tenant_name
  user_name   = var.openstack_user_name
  password    = var.openstack_password
}

# Look up the existing private network by name.
data "openstack_networking_network_v2" "private_network" {
  name = var.network_name
}

# -----------------------------
# Security groups
# -----------------------------

resource "openstack_compute_secgroup_v2" "web_sg" {
  name        = "web-security-group"
  description = "Allow SSH from anywhere and HTTP only from the internal subnet"

  # SSH is open so administrators (or the bastion-assisted Ansible run) can manage the host.
  rule {
    from_port   = 22
    to_port     = 22
    ip_protocol = "tcp"
    cidr        = "0.0.0.0/0"
  }

  # IMPORTANT:
  # Backend web servers should NOT be directly reachable from external networks.
  # This rule only permits the internal subnet to access the web service.
  rule {
    from_port   = var.web_port
    to_port     = var.web_port
    ip_protocol = "tcp"
    cidr        = var.subnet_cidr
  }
}

resource "openstack_compute_secgroup_v2" "lb_sg" {
  name        = "lb-security-group"
  description = "Allow SSH from anywhere and expose only the public load balancer port"

  rule {
    from_port   = 22
    to_port     = 22
    ip_protocol = "tcp"
    cidr        = "0.0.0.0/0"
  }

  # The load balancer listens publicly on 8082 (or whatever lb_port is set to).
  # We intentionally do NOT open port 80 here.
  rule {
    from_port   = var.lb_port
    to_port     = var.lb_port
    ip_protocol = "tcp"
    cidr        = "0.0.0.0/0"
  }
}

# -----------------------------
# Compute instances
# -----------------------------

resource "openstack_compute_instance_v2" "webserver1" {
  name            = var.webserver1_name
  image_name      = var.image_name
  flavor_name     = var.flavor_name
  key_pair        = var.keypair_name
  security_groups = [openstack_compute_secgroup_v2.web_sg.name]

  network {
    uuid = data.openstack_networking_network_v2.private_network.id
  }
}

resource "openstack_compute_instance_v2" "webserver2" {
  name            = var.webserver2_name
  image_name      = var.image_name
  flavor_name     = var.flavor_name
  key_pair        = var.keypair_name
  security_groups = [openstack_compute_secgroup_v2.web_sg.name]

  network {
    uuid = data.openstack_networking_network_v2.private_network.id
  }
}

resource "openstack_compute_instance_v2" "loadbalancer" {
  name            = var.loadbalancer_name
  image_name      = var.image_name
  flavor_name     = var.flavor_name
  key_pair        = var.keypair_name
  security_groups = [openstack_compute_secgroup_v2.lb_sg.name]

  network {
    uuid = data.openstack_networking_network_v2.private_network.id
  }
}

# -----------------------------
# Floating IP
# -----------------------------

# Only the load balancer gets a floating/public IP.
# The web servers remain private-only, which helps satisfy the requirement
# that they are not directly accessible externally on the web port.
resource "openstack_networking_floatingip_v2" "lb_fip" {
  pool = var.external_network_name
}

resource "openstack_compute_floatingip_associate_v2" "lb_fip_assoc" {
  floating_ip = openstack_networking_floatingip_v2.lb_fip.address
  instance_id = openstack_compute_instance_v2.loadbalancer.id
}

# -----------------------------
# Generated Ansible inventory
# -----------------------------

# Terraform renders the Ansible inventory so the configuration layer can
# automatically consume the infrastructure outputs.
#
# We configure the load balancer as a bastion/jump host for the web servers.
# This is helpful because the web servers only have private IP addresses.
resource "local_file" "ansible_inventory" {
  filename = "${path.module}/../ansible/inventory.ini"

  content = templatefile("${path.module}/../ansible/inventory.tpl", {
    ssh_user      = var.ssh_user
    private_key   = var.private_key_path

    web1_name     = openstack_compute_instance_v2.webserver1.name
    web1_ip       = openstack_compute_instance_v2.webserver1.network[0].fixed_ip_v4

    web2_name     = openstack_compute_instance_v2.webserver2.name
    web2_ip       = openstack_compute_instance_v2.webserver2.network[0].fixed_ip_v4

    lb_name       = openstack_compute_instance_v2.loadbalancer.name
    lb_private_ip = openstack_compute_instance_v2.loadbalancer.network[0].fixed_ip_v4
    lb_public_ip  = openstack_networking_floatingip_v2.lb_fip.address

    web_port      = var.web_port
    lb_port       = var.lb_port
  })
}
```

## `ansible/playbook.yml`

```yaml
---
# This play configures the two backend web servers.
- name: Configure web servers
  hosts: web
  become: true
  vars:
    # inventory_hostname will be "webserver1" or "webserver2".
    # We use it to generate distinct content per server.
    server_identity: "{{ inventory_hostname }}"

  tasks:
    - name: Install nginx on web servers
      ansible.builtin.package:
        name: nginx
        state: present

    - name: Deploy distinct HTML landing page
      ansible.builtin.template:
        src: templates/web-index.html.j2
        dest: /var/www/html/index.html
        owner: root
        group: root
        mode: "0644"
      notify: restart nginx

    - name: Configure nginx default site to listen on the shared web port
      ansible.builtin.copy:
        dest: /etc/nginx/sites-available/default
        owner: root
        group: root
        mode: "0644"
        content: |
          server {
              listen {{ web_port }} default_server;
              listen [::]:{{ web_port }} default_server;

              root /var/www/html;
              index index.html index.htm;
              server_name _;

              location / {
                  try_files $uri $uri/ =404;
              }
          }
      notify: validate and restart nginx

    - name: Ensure nginx is enabled and started on web servers
      ansible.builtin.service:
        name: nginx
        enabled: true
        state: started

  handlers:
    - name: restart nginx
      ansible.builtin.service:
        name: nginx
        state: restarted

    - name: validate and restart nginx
      block:
        - name: Validate nginx configuration on web servers
          ansible.builtin.command: nginx -t
          changed_when: false

        - name: Restart nginx after valid configuration
          ansible.builtin.service:
            name: nginx
            state: restarted

# This play configures the load balancer host.
- name: Configure load balancer
  hosts: loadbalancer
  become: true
  tasks:
    - name: Install nginx on load balancer
      ansible.builtin.package:
        name: nginx
        state: present

    - name: Remove default nginx site symlink so port 80 is not exposed accidentally
      ansible.builtin.file:
        path: /etc/nginx/sites-enabled/default
        state: absent
      notify: restart nginx

    # We place the load balancer config in conf.d and validate it before
    # allowing Ansible to replace the file. This reduces the risk of pushing
    # broken nginx syntax into production.
    - name: Deploy nginx load balancer configuration
      ansible.builtin.template:
        src: templates/nginx-lb.conf.j2
        dest: /etc/nginx/conf.d/loadbalancer.conf
        owner: root
        group: root
        mode: "0644"
        validate: "nginx -t -c %s"
      notify: restart nginx

    - name: Ensure nginx service is enabled and started on load balancer
      ansible.builtin.service:
        name: nginx
        enabled: true
        state: started

    - name: Final nginx validation on load balancer
      ansible.builtin.command: nginx -t
      changed_when: false

  handlers:
    - name: restart nginx
      ansible.builtin.service:
        name: nginx
        state: restarted
```

# The upstream block defines the backend servers that will receive proxied traffic.
# Because we do not specify another balancing method, nginx uses round-robin by default.
upstream backend_app {
    server {{ hostvars['webserver1'].ansible_host }}:{{ web_port }};
    server {{ hostvars['webserver2'].ansible_host }}:{{ web_port }};
}

server {
    # The load balancer must listen on the externally exposed port only.
    listen {{ lb_port }};
    listen [::]:{{ lb_port }};

    server_name _;

    location / {
        proxy_pass http://backend_app;
        proxy_http_version 1.1;

        # These headers preserve useful request information for backend services.
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

```bash

# Improvements made and why they matter

## 1. Added bastion/jump-host access for private web servers
### Change
Used the load balancer’s public IP as an SSH jump host in `inventory.tpl`.

### Why
In the original design, the web servers had only private IPs. That is good for security, but Ansible from your laptop often cannot reach them directly. Using `ProxyJump` makes the design both secure and operationally usable.

### Benefit
- more realistic deployment model
- preserves private-only backend servers
- avoids adding public IPs to web servers

---

## 2. Removed recursive variable pattern in Ansible
### Change
Did not keep:

```yaml
web_port: "{{ web_port | default(80) }}"
```

### Why
This is confusing and can lead to self-referential variable behavior. The ports are already defined in Terraform and injected into inventory.

### Benefit
- simpler variable handling
- less surprising behavior
- easier for beginners to understand

---

## 3. Improved NGINX config safety
### Change
Used `validate` on the LB template and explicit `nginx -t` before restart for web servers.

### Why
Pushing broken web server config can take a service down. Validation before restart is a classic safety practice.

### Benefit
- safer configuration changes
- easier troubleshooting
- better operational reliability

---

## 4. Strengthened secret-handling guidance
### Change
Removed any example suggesting a real password value inside a committed file and added `.gitignore`.

### Why
Terraform state and tfvars frequently become secret leakage points.

### Benefit
- better compliance with “do not hardcode credentials”
- better security hygiene for junior engineers

---

## 5. Added teaching-focused inline comments
### Change
Commented the Terraform, inventory, and Ansible files.

### Why
The user explicitly asked for tutor-style explanation for juniors.

### Benefit
- improves onboarding
- teaches key IaC concepts like variables, state, security groups, and templating
- makes the code easier to maintain

---

## 6. Preserved least-privilege network exposure
### Confirmed
- web servers: no public IPs and HTTP only from internal CIDR
- load balancer: only port `8082` exposed externally
- no SG rule for LB port 80
- nginx on LB listens only on `lb_port`

### Benefit
- aligns with requirements
- reduces attack surface
