# Infrastructure as Code (IaC) Summary

## Overview

Infrastructure as Code (IaC) is the practice of managing and provisioning computing infrastructure through machine-readable configuration files rather than manual processes. It delivers value through **repeatability** (same configuration across environments eliminates drift), **audibility** (every change is a Git commit with a permanent record), and consistent infrastructure management.

## Ansible

Ansible is an **agentless IT automation tool** that connects to target systems primarily via SSH. It pushes small modules to managed nodes from a control node without requiring agents, reducing overhead compared to agent-based alternatives. Key characteristics:

- Infrastructure is defined as desired state in **YAML playbooks**; rerunning playbooks converges systems to the same result (idempotent modules).
- Supports **mutable infrastructure** — changes are applied directly to existing systems, which offers flexibility but can accumulate configuration drift over time. Drift can be addressed through periodic playbook execution and monitoring.
- Can automate full AWS web stacks (VPC, security groups, EC2, ALB) and deploy software like Nginx across environments.
- **Prerequisites**: Python 3.8+, Ansible 2.14+ on the control node.

Example deployment playbook structure (`playbooks/deploy.yml`):

```yaml
---
- name: Deploy Web Application
  hosts: localhost
  connection: local
  gather_facts: false
  pre_tasks:
    - name: Display deployment information
      ansible.builtin.debug:
        msg:
          - ' '
          - 'Web Application Deployment Playbook'
          - ' '
          - 'This playbook will:'
          - ' - Install Nginx on EC2 instances'
          - ' - Deploy custom web application'
          - ' - Configure and start services'
          - ''
          - 'Note: Instances are in private subnets'
          - 'Connection method: AWS Systems Manager (SSM)'
          - ' '
    - name: Refresh dynamic inventory
      ansible.builtin.meta: refresh_inventory

- name: Configure web servers
  hosts: role_webserver
  gather_facts: true
  vars_files:
```

## Terraform

Terraform is an IaC tool that uses **HCL (HashiCorp Configuration Language)**, a domain-specific language with blocks, arguments, and expressions. The core workflow consists of four commands:

- **Init**: Initialize the working directory and download necessary providers
- **Plan**: Preview changes before execution
- **Apply**: Execute the plan to reach the desired state
- **Destroy**: Decommission managed infrastructure

Terraform supports **input variables** that act as parameters settable externally (files, environment variables, runtime) for reusing infrastructure code across environments.

### OpenStack Provider for Terraform

The OpenStack provider allows interaction with OpenStack resources. Example configuration:

```hcl
# Define required providers
terraform {
  required_version = ">= 0.14.0"
  required_providers {
    openstack = {
      source  = "terraform-provider-openstack/openstack"
      version = "~> 1.53.0"
    }
  }
}

# Configure the OpenStack Provider
provider "openstack" {
  user_name   = "admin"
  tenant_name = "admin"
  password    = "pwd"
  auth_url    = "http://myauthurl:5000/v3"
  region      = "RegionOne"
}

# Create a web server
resource "openstack_compute_instance_v2" "test-server" {
  # ...
}
```

Key configuration arguments include `auth_url` (or `OS_AUTH_URL` environment variable) and `cloud` (one of the two is required). A development environment can be set up using **DevStack** for testing and contributions.
