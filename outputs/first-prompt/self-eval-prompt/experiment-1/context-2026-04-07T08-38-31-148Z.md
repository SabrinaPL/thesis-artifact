# Retrieval Context

## Prompt Label
self-eval-prompt

Terraform IaC best practices emphasize making your configuration predictable, maintainable, and safe to change by applying consistent software-engineering hygiene to infrastructure code. Key recommendations include keeping formatting and syntax consistent across the codebase and running automated checks on every change to prevent drift in style and catch errors early—specifically using:

- `terraform fmt` to enforce consistent formatting
- `terraform validate` to verify configuration correctness

Standardization is a recurring theme: adopt consistent naming and folder conventions for resources, variables, files, and modules so the codebase is easy to navigate and refactor. Apply a consistent tagging strategy (e.g., owner, environment, cost-center, application) to improve governance, auditing, and cost tracking.

To strengthen operational safety, introduce policy as code to enforce security/cost/approval guardrails in an automated and reviewable way. Establish a secrets management approach that keeps secrets out of both code and Terraform state by storing them in a dedicated secret manager and passing references rather than raw secret values.

Finally, treat Terraform like production software: add automated tests so changes fail fast before reaching production, and make debugging/troubleshooting repeatable by enabling debug logging only when necessary and capturing sufficient context to reproduce issues.
